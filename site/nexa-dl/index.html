NEXA CLI

nexav3.8.0

A self-contained AI coding agent for Japanese SI delivery. Scaffolds the full six-phase SDLC, drives requirement and design generation, validation gates, and a FARE knowledge base. One tarball - no monorepo, no registry auth.

intake→RD→BD→DD→coding→delivery

01 Install

One line. The installer checks Node, resolves the latest version, and installs globally.

install.sh
$curl -fsSL https://downloads.agilekit.cc/nexa-dl/install.sh | bash

Or install the tarball directly with npm:

npm
$npm i -g https://dl.agilekit.cc/nexa-3.8.0.tgz

Then verify:

shell
$nexa --version && nexa doctor

Every native addon (better-sqlite3, koffi, …) ships prebuilt and bundled, and install scripts are stripped at pack time - no compiler, no network build step, no --ignore-scripts.

02 Activate

Activate the signed .license file supplied by your NEXA maintainer. Keep it private.

license file
$LICENSE_FILE="$HOME/Downloads/nexa.license"
$chmod 600 "$LICENSE_FILE"
$if (
$  set +x
$  NEXA_LICENSE_KEY="$(tr -d '\r\n' < "$LICENSE_FILE")"
$  nexa license activate "$NEXA_LICENSE_KEY"
$); then
$  nexa license status
$else
$  activation_status=$?
$  exit "$activation_status"
$fi

Confirm Revalidation: ✓ valid and Revocation: ✓ not revoked. If status says offline - using cached verdict, local signature and expiry checks passed, but current revocation status was not confirmed. Restore network access and check again.

Do not commit, upload, paste, or attach the license to tickets or logs. Direct activation with nexa license activate 'NEXA-<key>' is supported, but can save the key in shell history. Prefer the file-based procedure above.

Normal upgrades and reinstalls under the same user and HOME preserve ~/.nexa/license.json. Licenses signed by the verifier retired before alpha.22 must still be reissued and activated again. On a new machine or under a different HOME, securely transfer the original .license file and activate again. Expired licenses stop immediately. Revoked licenses stop after the revoked verdict is fetched and cached; while offline, NEXA uses the last cached revocation verdict.

03 Update

Already installed? Upgrade in place with the built-in self-updater.

nexa upgrade new
$nexa upgrade              # fetch latest, install over the current one
variants
$nexa upgrade --check                   # current vs latest, no install
$nexa upgrade --version 3.2.0-alpha.11  # pin / roll back
$nexa upgrade --dry-run                 # print the install command only

No global command yet (on an older build)? Re-running the installer is equivalent and idempotent: curl -fsSL https://downloads.agilekit.cc/nexa-dl/install.sh | bash.

04 Quick start

Scaffold and inspect a project. Full greenfield sequence in QUICKSTART.md.

shell
$mkdir my-project && cd my-project
$nexa init        # scaffold 6-phase folders + .claude + .nexa + config
$nexa status      # workspace / kb / doc / gate health
$nexa scan all    # build the FARE knowledge base
$nexa tui         # launch the coding agent

05 Requirements

  • Node 22.19+ and npm - the installer checks and stops with a clear message otherwise.
  • macOS or Linux. A prebuilt better-sqlite3 is bundled for the knowledge base (nexa kb / nexa scan). init, status, doctor work regardless.
  • Mismatched Node ABI (e.g. Node 24/26) and a native-module error from nexa kb? Rebuild the bundled engine once - source ships too, so it works offline:
    only if kb reports a native error
    $npm rebuild better-sqlite3 --prefix "$(npm root -g)/@fabbi-product-nexa/nexa-cli"
  • No GitHub or npm registry auth - all 15 internal packages are bundled into the tarball.
  • No Node on the machine? NEXA Agent is the same NEXA with its own Node runtime: one installer for macOS, Linux and Windows, no npm.
